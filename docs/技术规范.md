# Between Us 技术规范

## 技术栈
- React 19
- TypeScript
- Vite
- Lucide React 图标
- localStorage 浏览器持久化

## 项目结构
- src/App.tsx：页面状态、交互流程、模拟分析逻辑
- src/index.css：全局视觉、布局、响应式样式
- src/main.tsx：React 入口
- scripts/daily-log.mjs：每日开发日志自动生成脚本
- docs/：项目需求、技术、设计和执行文档
- dev-log/：按日期保存的开发日志

## 状态模型
Stage 包含：
- home：首页
- describe：事件描述（整体概括 + 六层深挖回溯）
- review：梳理与编辑（情绪画布 + 情绪逐层探索）
- timeline：时间线地形（map 探索 / explore 节点逐问回溯）
- perspective：视角对话（friend 朋友视角 / observer 静观）
- complete：完成页

已移除 comparison（视角对照）与 reflection（反思总结），其职责由静观收尾替代。

Analysis 使用 CategoryKey 作为键：
- facts
- interpretations
- emotions
- needs

## 数据持久化
浏览器刷新时保存以下数据：
- 当前阶段 stage
- 事件原文 eventText
- 编辑后的分析结果 analysis
- 已探索首页章节 exploredSections

存储键：between-us-state

## 分模块数据建议
后续数据结构应显式区分：
- evidence：可确认事实
- interpretation：用户主观理解
- assumptions：对对方想法的假设
- unknown：暂时无法确定的信息
- emotions：情绪变化
- needs：内在需求
- timeline：冲突阶段与节点

对方视角数据禁止只使用普通 narrative 字段直接展示为事实；必须携带确认程度或来源，例如 uncertain、user-provided 或 user-rejected。

TimelineNode 应保留以下回溯字段：
- event：触发事件事实或用户描述
- time：相对时间或明确时间；无具体时间时不得自动生成日期
- quote：用户记得的原话或明确标记为记不清
- behavior：印象深刻的行为、表情或动作
- response：用户当时的回应
- emotion：用户当时的情绪
- aftermath：冲突后的可确认变化
- interpretation：用户对事件的理解
- missing：仍未知的信息
- status：confirmed、pending 或 unknown

视角对话模块至少保留：
- perspectiveMode：friend / observer
- friendMessages / observerMessages：双通道消息
- friendPerspectiveComplete：朋友视角收尾标记
- observerComplete / observerWrapUp：静观收尾标记与整理结果（完成页展示）

回溯深挖数据：
- guidedAnswers：六层回溯答案（时间背景、对话原话、表情语气、反应、错位、情绪需求）
- guidedMedia / nodeMedia：引导层与时间线节点的本地压缩图片（每处最多 3 张）
- emotionDrills：情绪逐层探索记录 { feelings, custom, reflection, needs }

时间线节点按 phase（Before / Trigger / Conflict / Aftermath / 补充回忆）使用不同问题集；节点派生状态由 nodeAnsweredCount / nodeDerivedStatus 计算（全部答完且无未知项 → confirmed）。

## 动态叙事状态
- `src/narrativeEngine.ts` 提供模拟叙事引擎、阶段骨架、分支判定和检查点回退。
- `NarrativeState` 保存阶段、问题、交互类型、历史对话、事件档案、场景、分支和完成状态。
- 事实、理解、情绪、未知信息分别存储，禁止将假设写入事实数组。
- 前端只消费结构化状态决定文案和控件，不允许叙事引擎控制页面组件。

## 对话通道与模拟引擎
- `src/chatProvider.ts`：对话通道统一入口。`streamChat({ channel, message, history, context, onDelta })` 按 `VITE_USE_REAL_LLM` 切换：
  - false（当前阶段默认）：本地模拟引擎，不接入真实 AI API；
  - true：调用 `POST /api/chat`（SSE 流式，`friend` / `observer` 通道），页面代码无需改动。
- `src/mockChatEngine.ts`：规则化模拟引擎。根据事件细节（原话、表情/动作、回应、经过）生成“细节观察 + 一个问题”的回复；检测收尾关键词后生成“关键发现 + 未知项”整理。同时提供情绪逐层探索的规则映射（感受选项、反思问题、需求推导）。
- 情绪逐层探索的规则映射同样预留真实 API 接口：未来可由大模型生成反思问题与需求推导。
- 真实 API 接口契约：`POST /api/chat { channel: 'friend' | 'observer', message, history }` → SSE `data: {"text": "..."}`，`event: done` 结束。

## 命令
- npm.cmd run dev：启动开发服务器并自动记录日志
- npm.cmd run server：启动 DeepSeek SSE 后端，监听 127.0.0.1:3001
- POST /api/chat：接收 `{ message, history }`，通过 SSE 流式返回生成文本
- npm.cmd run build：执行类型检查、构建并记录日志
- npm.cmd run lint：运行代码检查
- npm.cmd run test:narrative：叙事引擎回归测试
- npm.cmd run test:mock：模拟对话引擎测试（细节锚定、单问题、收尾整理、情绪映射）
- npm.cmd run preview：预览构建结果
- npm.cmd run log：手动生成或更新今日开发日志

## Windows 启动
项目根目录的 start.bat 会启动 Vite 开发服务器。
