# Between Us 产品需求规格

## 产品定位
Between Us 是一个 AI 辅助的友情冲突反思工具，核心理念是：

> 不替你定义关系，只陪你重新看见关系。

产品主要解决友情冲突中的单一视角、反复猜测对方想法、事实与主观判断混淆，以及不知道如何重新理解关系的问题。

产品原则：
- 不判断谁对谁错。
- 不替用户决定是否修复关系。
- 只帮助用户重新理解一段关系。
- 保持语言克制、不评判、不指责。
- 对方的想法只能呈现为假设，不能包装成事实。
- 用户始终可以修改、否定、删除或保留不确定信息。

## 核心能力
- 冲突事件记录：通过文字描述友情冲突的经过。
- 深挖式回溯：引导用户回忆具体日期、对话原话、表情语气与交流错位，支持语音与图片补充细节。
- 事件与情绪梳理：区分事实、主观判断、情绪反应和内在需求。
- 情绪逐层探索：点击情绪碎片，逐层追问背后感受、反思问题与内在需求，把情绪识别转化为需求识别。
- 时间线回溯：按节点阶段（冲突前、矛盾触发、冲突发生、关系变化）分别深挖，节点完成后点亮并保留各节点独立进度。
- 双视角转换：在“我的视角”和“对方可能的视角”之间切换（朋友视角对话通道）。
- 静观第三方视角：中立观察对话，锚定事件具体细节，一次一个观察、一个问题；收尾时整理关键发现与未知项。
- 未知区域识别：对无法确定的动机、想法和感受保留模糊或留白。

## 完整页面规划
规划中的页面包括：
1. 首页：展示产品名称、核心理念、简介和开始入口。
2. 事件记录页：输入友情冲突的经过，并进行六层深挖式回溯。
3. 事件梳理页：展示并允许修改事实、判断、情绪和需求，支持情绪逐层探索。
4. 时间线回溯页：以节点呈现冲突发展过程，按节点阶段分别深挖并点亮。
5. 视角转换页：朋友视角对话通道，对方想法始终标记为假设。
6. 静观页：第三方观察对话与收尾整理（原视角对照与反思总结由静观收尾替代）。
7. 完成页：展示静观整理结果，可返回或开始新的梳理。

完整规划不要求第一阶段一次性实现。后续必须按模块分阶段开发。

## 分阶段范围
第一阶段：
- 首页或当前原型入口。
- 事件记录页（含深挖式回溯与语音/图片补充）。
- 事件梳理页（含情绪逐层探索）。
- 编辑、删除、新增、确认、完成和浏览器本地保存。

第二阶段：
- 时间线回溯（按节点阶段差异化提问与点亮反馈）。

第三阶段：
- 双视角转换（朋友视角对话通道，本阶段为本地模拟引擎）。

第四阶段：
- 静观第三方视角与收尾整理（替代原“未知区域与视角对照”独立页）。

第五阶段（后续）：
- 反思总结与沟通表达草稿（当前已由静观收尾替代，草稿能力留待后续恢复）。

## 当前原型已覆盖
- 首页展示产品核心理念与章节光点入口。
- 六层深挖式引导回溯（时间背景、对话原话、表情语气、反应、错位、情绪需求），支持语音与图片补充。
- 情绪碎片画布与情绪逐层探索（感受 → 反思问题 → 需求识别）。
- 时间线回溯按节点阶段差异化提问、节点点亮与独立进度。
- 朋友视角与静观双对话通道（本阶段为本地模拟引擎，预留真实 API 接口）。
- 静观收尾整理（关键发现 + 未知项）与完成页。
- 反思总结页与视角对照页已由静观收尾替代。

## 用户流程
1. 用户在事件描述页填写最近发生的冲突。
2. 事件描述流程采用整页切换，不把概括、四层回溯和操作按钮塞在同一个复合面板内。
3. 第一页要求用户用一两句话概括整件事；确认后整个页面切换到第一层回溯。
4. 后续每一层都是独立全屏页面：关系背景、关键时刻、反应与判断、此刻感受与需求。
5. 系统提供3至4个“AI 可能的回忆选项”，用户可直接选择或取消，显著减少描述负担。
6. 用户仍可通过自由描述栏补充、修改或否定预测选项。
7. 每一层包含亲切提示和温和示例，用户可填写、跳过或返回修改。
8. 系统将简短概括和已有回答按顺序整理为事件原文，再进入结构化梳理。
9. 事件为空时禁止提交。
10. 提交后进入情绪碎片梳理画布：
   - 事实 Facts
   - 主观判断 Interpretations
   - 情绪 Emotions
   - 内在需求 Needs
梳理页只整理用户当前的情绪状态，不完整复述事件。展示应优先使用一至两个词或极短句，避免大段文字和分类卡片堆叠。
11. 用户可悬停或点击轻量碎片进行编辑、删除，并通过“留下一个感受”入口补充内容。
12. 用户确认梳理结果后进入完整页面切换的时间线地形回溯。
13. 时间线节点、双视角图层、视角对照和反思总结均采用整页探索画面，操作后平滑切换，不叠加卡片面板。
14. 完成页可返回梳理页修改，也可开始新的梳理。

## 功能要求
- 输入限制为 3000 字。
- 提交时展示加载状态。
- 本阶段不接入真实 AI API：朋友视角与静观对话使用本地模拟引擎（规则化、锚定事件细节），代码通过 `VITE_USE_REAL_LLM` 开关与 `src/chatProvider.ts` 预留真实大模型 SSE 接口（`POST /api/chat`，`friend` / `observer` 通道）。
- 引导式回溯支持语音输入（浏览器 Web Speech API，不可用时降级提示）与图片补充（本地压缩存储，每层最多 3 张）。
- 时间线节点按阶段使用不同回溯问题；节点全部回溯完成后点亮并保留各节点独立进度。
- 编辑结果保存到浏览器 localStorage。
- 刷新页面后保留当前阶段、原文和梳理结果。
- 包含进度指示、重新梳理、返回修改和移动端响应式布局。

## 验收标准
- 空白输入时“开始梳理”不可点击。
- 输入有效内容后可进入梳理页。
- 梳理画布只展示少量极短情绪碎片，不完整复述事件。
- 四个分类内容仍可通过悬浮碎片编辑、删除或补充。
- 删除后条目立即消失。
- 空新增内容不可提交。
- 确认后进入完成页。
- 开始新的梳理后清空原文和结构化结果。

## 时间线探索空间
- 时间线展示为可拖动的关系地形，不使用固定横向步骤条。
- 节点状态区分已确认、待补充和未知三种视觉状态。
- 进入节点后，每次只显示一个回溯问题，并提供关键词选项、简短补充和跳过能力。
- 回溯顺序覆盖触发、时间、原话、行为、用户反应、情绪和后续影响。
- 已填写内容不得重复要求用户再次组织；用户可返回修改已确认回答。
- 节点保存事实、理解、假设和未知信息，AI 推测不得伪装为已发生事实。

## 视角转换
- 根据时间线节点逐个进入场景，不一次铺设双方卡片。
- 已确认对话和行为直接呈现；对方反应始终标注为假设。
- 用户可选择假设提示或明确保留未知。
- 禁止把视角转换设计成责任比例、虚构对话或替对方作出真实回应。

## 动态叙事回溯
- 视角转换使用视觉小说式逐句叙事，以传统聊天软件式的圆润气泡呈现已确认的双方交流。
- 页面主区域只保留朋友与用户的对话气泡、气氛背景和必要的橙色事件节点。
- 未确认的朋友原话必须保持模糊或明确标记为未知，不得使用虚构台词。
- 模拟叙事引擎根据回答进入消息、面对面或行为分支。
- 每次只展示一个核心问题，并提供关键词选项、自由补充、跳过和返回修改。
- 界面区分已确认事实、用户理解、情绪和仍然未知的信息。
- AI 模拟输出结构化叙事状态；真实 API 接口可替换，但不得让模型直接控制页面代码。
